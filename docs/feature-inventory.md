# PathHunter feature inventory

Status comes from the current Java sources and from the smoke harness in `build/smoke/results.txt`. Only features that exist in source (and, where noted, harness output) are marked Implemented / Partial / Payload only. Planned PathHunter roadmap items are **not** listed here as implemented.

"Implemented" means the current source contains a working path that the harness or a direct read confirmed. "Partial" means the source contains the feature and a verified gap changes the result. "Payload only" means the extension generates strings and does not perform the HTTP upload itself. "Not implemented" means historical README/`TODO` names it and the current source does not do it.

| Feature | Source location | Implementation status | Limitations |
| --- | --- | --- | --- |
| Absolute filesystem paths | `PsychoPanel2` Absolute paths tab; `AbsolutePathEngine`; `IntruderPayloadGenerator.appendAbsolutePathPayloads` | Implemented | Off by default. Emits bare paths such as `/etc/passwd` and `C:\Windows\win.ini` without `../` or webroot prefixes. Linux/Windows/Custom lists with validation. Encoding uses existing tables once per enabled index. AbsolutePathSmoke 33/33. |
| URL encoding / decode-order bypass | `PsychoPanel2` URL Encoding tab; `UrlEncodingEngine`; `IntruderPayloadGenerator.appendUrlEncodingPayloads` | Implemented | Off by default. Independent of legacy `encodingsEnabled` pipeline. Depth 1–5 (default 2), mixed/case/separator variants, decode-stage preview. UrlEncodingSmoke 31/31. |
| File Upload Request Analyzer | `fileupload.FileUploadRequestAnalyzer`, `MultipartParser`, `FileSignatureInspector`, `FileUploadPanel`; `Menu` context action; `PsychoPanel2` File Upload tab | Implemented | Passive only. Harness: suffixes contained `/images` and `/css` after those values were added to `genericSuffixes`, and `/should-not-appear` stayed out after it was written only to `suffixesList`. | Windows support | `addWindows`, slash setting `win`, `win.ini`, `windowsDocroots`, `drivesList` | Partial | Harness produced `win.ini` and `..\win.ini`. `addWindows` does not add encoded backslash spellings into an empty `slashesToUse`. | Encoding | `encodingsEnabled` indexes 0-5; tables at `IntruderPayloadGenerator` lines 190-204; checkboxes in `PsychoPanel2` | Partial | URL encoding is on by default and the harness produced `%2e%2e%2f%2e%2e%2fetc%2fpasswd`. UTF-16 and overlong ranges exist in the tables and default to off. |
| Evasive techniques | `evasiveList`, `breakupList`, `mixedSlashEvasiveTraversals`, mixed-encoding loops | Implemented | Defaults include `....//`, `...//`, `.....///`, and `.{BREAK}.{BREAK}/` with break byte `20`. | Byte generator | `IntruderPayloadGeneratorByte`; combo in `PsychoPanel2.byteGeneratorRangeComboActionPerformed` | Partial | Six ranges are implemented. Alphanumeric emitted 62 payloads in the harness. Global output encoding is commented out, which disagrees with the README and with `TODO` line 6. An unknown range throws `NullPointerException`. |

## Defaults that change which feature runs

LFI mode starts enabled, so a fresh Intruder "Path traversal" generator does not walk the document-root list until the user clears "LFI mode (don't use webroots)". The smoke test confirmed `LFImode=true` immediately after `registerExtenderCallbacks`.
